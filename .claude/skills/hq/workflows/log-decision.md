# Log a decision

## Purpose

Write down a business decision in one line, with the date and the reason, so it doesn't get debated again and every department works from it.

## Use when

The owner says "note that we've decided…", "write that down", "we're dropping the monthly plan", "from now on we…", or makes a clear decision in the middle of another job.

## Load first

- `memory/decisions.md` (to see the format and check this isn't already there)
- `business/goals.md` and `business/offers.md` (only if the decision changes them)

## Steps

1. **Pin the decision.** Write it as one short, plain sentence: what was decided, not the discussion ("Stop offering single sessions; sell the 6-week package only"). If it's unclear what exactly was decided, ask one question.
2. **Get the reason.** Use the reason the owner gave. If they didn't give one, ask: "What's the main reason, in a few words?" If they'd rather not say, write "not given".
3. **Check for a clash.** Look in `memory/decisions.md` for an earlier decision this replaces or contradicts. If there is one, say so in one line and note in the new entry that it replaces the one from that date. Don't delete the old line.
4. **Append it.** Add a new row at the bottom of the table: today's date (`YYYY-MM-DD`), the decision, the reason.
5. **Spot knock-on changes.** If the decision changes another file (an offer is dropped, a price changes, a goal moves, a rule about tone), say which file and offer to update it. Show the exact change and wait for a yes before editing. A price change in a live tool (a booking page, a payment link) is a money action and needs its own yes.
6. **Confirm.** Tell the owner in one line what you saved.

## Check before handing over

- One row, one decision, in plain words someone else would understand in six months.
- The date is today's date.
- The reason is the owner's, not one you came up with.
- No earlier entries were edited or removed.

## Save to

Append to `memory/decisions.md`. If the file doesn't exist yet, create it with a `Date | Decision | Why` table first.

## Needs a yes

Appending to `memory/decisions.md` is fine without asking. Editing any other file as a knock-on (offers, goals, rules) needs a yes on the exact change. Changing a price in a live tool needs a separate, explicit yes.
